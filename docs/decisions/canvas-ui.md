# canvas-ui — design decisions

## Decide stage — `apps/web/src/decide/`, `apps/web/src/lib/decide.ts`

- **Runs are computed from the model, not taken from the Test stage.** `computeDecideData` runs the baseline and one run per scenario (≤ 8) on the main thread, plus loops, leverage, Model Health, OAT sensitivity of the first KPI and Loops That Matter. The brief therefore always matches the current model, even if the user never pressed Run. It re-runs only when the structure changes (`variables`, `links`, `scenarios`, `simSpec`, `frame`, …), not when the decision text or interventions change. A part that fails (a scenario whose override does not compile) is left out and listed under the comparison; a core stub that has not landed (`rankLeverage`) falls back to the structural ranking.
- **Preview = the report's own HTML in `<iframe sandbox="allow-same-origin allow-modals" srcdoc>`**: no `allow-scripts`, so model text can never execute, and the stage never uses `innerHTML`. `allow-same-origin` lets the Print button call the frame's `print()` (print needs `allow-modals`); both are safe without scripts. Print prints only the report, not the app.
- **E2E console filter.** A script-less sandboxed frame makes Chromium log "Blocked script execution in 'about:srcdoc' …" once per frame load whenever Playwright is attached (reproduced on a bare `<iframe sandbox srcdoc>`; the app injects no script). `apps/web/e2e/helpers.ts` exports that one message as `SANDBOX_NOISE`; `trackConsole` and `shell.spec.ts` skip exactly it. Every other console error still fails the "zero console errors" specs.
- **Scenarios: one small "Add scenario" control.** Name + one constant + one new value (`addScenario` in `lib/edits.ts`; the equation is the number's plain text, so the engine reads it as a literal). Only constants are offered, so a user-made scenario can never create an equation that fails to compile; the value must be finite and the name non-empty. It sits under the interventions so a new scenario can be linked at once. Multi-override or equation-valued scenarios still come from examples or the copilot, and a full scenario editor stays a follow-up (SPEC §8 places scenarios in Test).
- **Link status coupling.** Linking a scenario to an `idea` intervention sets it to `tested`; unlinking a `tested` one sets it back to `idea`. Any other status is left alone.
- **CSV export** is per run (a select picks Baseline or a scenario), via core's `toCsv`; time vectors of scenarios with their own `simSpec` can differ, so runs are not merged into one file.
